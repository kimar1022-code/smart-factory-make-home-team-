### 신설 `tools/hover_align.py` — 호버 정렬(오프라인 실증, 실기 미투입)
- z_seat+85 에서 **든 벽 점 ↔ 베이스 특징(기둥 점 + 안착된 벽 점)** 을 같은 손목캠 프레임에서 기준 관계에 맞춘다. 파지가 어디를 물었든 무관해진다.
- δ_robot = R(rz−180)·Jinv_obs·(d_h/377)·Δpx. **손목캠이라 rz 회전 매핑 필수** — 없으면 90° 틀린 답.
- 사용자 nudge 프레임 3건(노랑 z441)으로 검증: 예측 (+2.12,−0.60)/(−0.10,+0.89)/(+2.21,−1.49) vs 실제 (+2,−1)/(0,+1)/(+2,−2).

- red_s 는 z440(rz 83)에서 베이스가 화면에 없음 → 정렬 자세 별도 티칭 필요.

## 9/7 (마감일) — 벽 삽입 자동화 `house_cycle` 실기 완성

5색 벽 지원: `blue` / `yellow` / `red` / `red_s` / `red_in`(내벽, 흰 바탕 빨간 점, 두께 4mm, 별도 랙).
**4벽 반복 삽입 성공**, 랙→z440 무개입, 정렬 잔차 0.42~1.87mm(한계 4.0), 자동 안착 판정 첫 성공(빨강 19:22 · 파랑 19:36 — 호버/안착/슬롯 기준 3종 자동 승격).

### 진범 1 — 빨강 색상 wrap-around (오늘 최대 발견)
빨간 점은 HSV 색상환에서 H≈0~17 과 H≈135~179 **양쪽에 걸쳐** 있는데 한쪽 구간만 쓰고 있었다.
그래서 점이 통째로 안 잡히는 게 아니라 **조각만 잡혀** 면적 하한에 걸리거나 중심이 밀렸다 — red_s 가 셋 중 제일 까다로웠던 이유.
→ `WALL_DOT_HSV` 를 구간 **리스트**로 바꾸고 `_mask_ranges` 합집합으로 마스크 생성.

### 진범 2 — 중복 정의가 사고 5건의 원인
- 색 테이블이 `place_calc.py` 와 `hover_align.py` 두 곳에
- `HELD_AREA_MIN` 이 한 파일 안에 두 번
- 든 벽 검출 창의 y 상한이 한쪽 700 / 한쪽 715 → 같은 점이 한 경로에선 보이고 다른 경로에선 안 보여 **"하강 금지"**
→ 단일 출처로 정리. (남은 중복 경로 통합은 마감 후 과제)

### 진범 3 — 파지 서명을 찍는 자세·순서

#### 진범 — 내벽이 밑판 검출을 반으로 갈랐다
내벽을 꽂자 관측자세에서 **기둥 0/4** 가 나기 시작했다. 색점 검출은 멀쩡했고(파랑 6·노랑 4·빨강 10) 노출을 어떻게 바꿔도 안 됐다. 실제로는:

- 밑판 사각형이 `(510,300)~(779,599)` — **아래 칸만** 잡혔다. 위쪽 두 꼭짓점에 기둥 점이 없으니 꼭짓점↔색 배치 검증이 무너져 0/4.
