## 0. 먼저 정정 (이전 답변의 오류 2건)

| # | 이전 답변 | 정정 | 근거 |
|---|---|---|---|
| 정정1 | 긴벽 여유 "5.0−4.22 = 0.78, ±0.39, yaw 0.23°" | 긴벽은 **쐐기 끝 + 삼각 노치** 결합. 벽 플랫 면이 노치 바닥(y=2.5)에 닿고 반대쪽으로만 **약 1.0 mm** 유격(4 mm 삽입 기준). 목표 = 플랫 접촉 + 0.5 → 판 중심 **y≈5.0 (±0.5)**, yaw 허용 **0.29°**. 0.78/0.23°는 **짧은벽 직사각 노치**에만 맞다 | STL 단면 재계산(`tools/house_geometry.py` 상수) |

D435 사양·새 마운트 실측으로 확정 필요 |

## 1. 항목별 판정

범례: **적용** = 스펙에 반영(이 저장소에서 할 수 있는 만큼 함) · **조건부** = 사용자 결정 뒤 적용 · **보류** = 9/7 이후 · **불채택** = 이유 기재

| # | 제안 | 판정 | 우리 재설계와의 관계 / 이유 |
|---|---|---|---|
| 1 | 기준계는 베이스에 붙은 것만(책상 ArUco는 ZK 목표·드리프트 감시 전용) | **적용** | 4절 "형상 base_frame 채택, ArUco 폴백 강등"과 동일. 추가된 것은 "책상 마커의 남은 용도"뿐 |
| 2 | 뎁스로 기둥 꼭대기 4점 → 정밀 yaw | **불채택**(정정2) | 지시서 v2와 충돌하고, 정밀도가 허용치 대비 부족. 대신 **뎁스 역할 재정의**: (a) 기둥 꼭대기 4점 **거친 위치**(±1 mm)로 RGB 검출 ROI 제공, (b) 릴리즈 후 **높이 판정**(#8) |
| 3 | 밑판 바닥에 ArUco 2장 부착 → yaw 교차검증 | **조건부 적용** | 4절에 없는 신규. 베이스에 붙는 마커라 "책상 마커는 베이스 이동 못 봄" 문제와 무관하고, 형상 검출이 흔들릴 때 폴백이 된다. **조건**: 하드웨어 변경(스티커)이라 사용자 승인. 내벽(x≈137)·페그 구멍 4개·가구 자리를 피할 것. 두 마커 기선 ≥ 100 mm. 형상 결과와 0.2° 이상 불일치 시 정지 |
| 4 | 그리퍼 회전은 **J6 증분**으로만, 호버에서 완료 | **적용** | 7절 J6 규칙(±175, 대회전 봉인, \|ΔJ6\|>180 금지)과 정합. `target_tcp()`가 최소각 ΔJ6를 반환하도록 구현·검증 |
| 5 | 목표 TCP 식 (rz\* = θ_B+φ_slot−φ_grip, xy\* = T·p_slot − R(rz\*)·p_grip) | **적용** | 4절 3층 좌표계의 수식화. 회전 중심이 TCP라 \|p_grip\|·Δθ 이동이 포함됨을 테스트로 확인(40 mm×4° = 2.79 mm) |
| 6 | 호버 서보: yaw 먼저(J6) → XY(실측 자코비안), 종료 = 양끝 ≤ 허용의 60%, \|Δθ\| ≤ 허용의 60% | **적용** | 앞끝우선 러너(cam1 XY, cam2 yaw)를 뒤집은 것이 아니라 **순서만 yaw 우선**으로 바꾼 것. 이유: 회전이 XY를 2.8 mm 흔드니 XY를 나중에 맞춰야 반복이 준다. 회전 후 자코비안은 R(Δθ)로 돌려 재사용. 종료 문턱은 `alignment_ok()`로 고정 |
| 7 | 측면캠: **벽 윗변 픽셀이 명령 z만큼 안 내려오면 정지** | **적용** | 4절 "측면캠으로 삽입 감시"의 구체 신호. z-정체 감시가 못 잡던 "그리퍼서 얹힘"을 잡는다. side_slot.py 튜닝 대상이 바로 이 신호 |
| 8 | 릴리즈 후 뎁스로 벽 윗변 == 기둥 꼭대기 검증 | **적용** | 4절에 없던 신규. 80 mm 신호라 D435 정밀도 문제와 무관. 비용 거의 0 |
| 9 | 파지 z를 절대값 대신 **벽 윗변 기준 고정 깊이** | **적용** | 4절 "픽 = 랙위치 + 파지골든"을 대체하지 않고 **z만** 윗변 기준으로 바꾼다. 벽이 위아래로 움직여도 같은 깊이로 물린다. **주의**: D435 최소거리(고해상도 약 0.28 m)라 윗변 z는 호버 높이에서 재야 함. 이 거리에서 안 되면 USB캠으로 윗변 겉보기 길이(198/125 mm 기지)로 거리 추정(±2 mm면 충분, 아래 #10이 흡수) |
| 10 | 파지 후 재측정(제시 자세)으로 p_grip, φ_grip 매 사이클 확정 | **적용(홈포즈 골든 위에 덧씀)** | 골든 폐기가 아니라 **골든 = 공칭, 재측정 = 보정치**. 이유: 긴벽 3종은 홈포즈 골든으로 0.05 mm가 나왔고(9/3), 폐기하면 검증된 걸 버리는 셈. red_s처럼 3 mm 흔들리는 벽만 보정치가 크게 나온다. 게이트: 길이방향 > 1.0 mm 또는 그리퍼 내 기울기 > 0.2° → 정지·보고(자동 재파지 금지, 철칙) |
| 11 | 랙에 ArUco 1장 → 랙 프레임 | **보류** | 사진 3의 아크릴 가이드가 랙 위치를 구속하고 있어 랙 pose가 실제로 흔들리는지 **미확인**. 흔들린다는 데이터가 있을 때만. 랙 STL도 없음 |
| 12 | 노치 5.6 mm + 상단 1 mm 챔퍼 재출력 | **보류** | 9/7 전 재출력·재검증 시간 부족. 골든이 어차피 무효라 재티칭 부담은 같지만, 정정1로 긴벽은 이미 ±0.5라 급하지 않다. 9/7 이후 후보 |
| 13 | 정밀도 추정치(0.03°, 0.05°) | **불채택(수치)** | 정정2. 실측 전에는 문서에 목표치로만 둔다: 베이스 yaw 측정 목표 **≤ 0.1°** (긴벽 허용 0.29°의 1/3) |

## 2. 적용된 스펙 변경 (재설계 v2 → v2.1 차분)

메모리 4절을 기준으로 바뀌는 문장만 적는다.

1. **기준계**: 그대로(형상 base_frame). 단 **뎁스 역할**을 "거친 분리"에서 "거친 분리 + 기둥 꼭대기 ROI + 릴리즈 후 높이 판정"으로 확장. 정밀 yaw는 RGB.
2. **폴백**: ArUco 폴백을 "책상 마커"가 아니라 **"베이스 바닥 마커 2장"**으로 바꾼다(승인 시). 책상 마커는 ZK 목표·드리프트 감시.
3. **골든 재정의**: "밑판 기준 슬롯 자리"는 그대로. 슬롯 좌표를 STL 값으로 고정: 긴벽 y=5.0/135.0(x 6→204), 짧은벽 x=4.5/205.5(y 7→133). 허용: 긴벽 ±0.5 mm·0.29°, 짧은벽 ±0.39 mm·0.36°.
4. **픽**: "랙위치 + 파지골든" → "랙위치 + **윗변 기준 z** + 파지골든(공칭) + **파지 후 재측정(보정)**".
5. **정렬 루프**: yaw(J6 증분) → XY(자코비안, 회전 후 R(Δθ) 적용) → 종료 = 허용의 60%. 최대 3회. 기둥 꼭대기 아래 보정 금지(C2 유지).
6. **하강**: 측면캠 "벽 윗변 정체" 즉시 정지 + 들어올리기만. 릴리즈 후 뎁스 높이 판정.
7. **게이트 추가**: 베이스 |θ_B| 상한(사용자 결정, 제안 5°), 기울기 ≤ 1°, 형상↔마커 불일치 ≤ 0.2°, 파지 후 길이방향 ≤ 1.0 mm.

## 4. 남은 시간(D-3) 우선순위 제안

1. (내일, 로봇 필요) 브리지 재기동 → J6 가드. 새 마운트 base_view에서 **RGB 기둥 꼭대기/외곽선 검출 mm/px 실측** → 정정2의 정밀도 추정을 실측으로 교체.
2. 골든 재티칭을 **슬롯 좌표(STL) + 파지골든(홈포즈)** 조합으로. 로봇 자세 박제 골든은 만들지 않는다.
3. 측면캠 side_slot.py를 "벽 윗변 정체" 신호로 튜닝(벽 내리는 프레임 필요).
4. 파랑→노랑→빨강 재현 후에만 red_s(#10 보정치 + #7 측면 감시).
5. 베이스 바닥 ArUco(#3)는 1~2를 하는 동안 스티커만 붙여두면 나중에 켤 수 있다(승인 시).
