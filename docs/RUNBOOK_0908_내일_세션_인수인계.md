## 3. 내일 첫 할 일 — 내벽 풀사이클

**순서가 중요합니다: 내벽은 반드시 외벽 4개 다음, 마지막입니다.**

```
blue → red → yellow → red_s → red_in
```

이유: 내벽이 베이스에 꽂히면 밑판 뎁스 검출이 **위/아래 두 칸으로 끊겨** 기둥이 0/4 가 됩니다.
대응은 `base_depth_corner.INNER_WALL_MODE` 에 들어 있는데, **`stage_base(color)` 가 `color == "red_in"` 일 때만 켭니다**
(사용자 지시: "내벽하고 외벽 조건 따로 써", "외벽 다 끝나고 넣을 거니까 그때만 키게 해").
내벽을 먼저 꽂으면 그다음 외벽 사이클의 베이스 측정이 전부 실패합니다.

실행:

```bash
# 콘솔 :8776 에서 [▶ 시작] color=red_in  또는
curl -s "http://127.0.0.1:8776/cmd?op=start&color=red_in"
# z440 정렬까지 자동 → "WAIT DESCEND" 에서 멈춤 → 화면 확인 후 [⬇ 하강]
```

4벽 한 번에:

```bash
curl -s "http://127.0.0.1:8776/cmd?op=run4&order=blue,red,yellow,red_s"
```

⚠ run4 는 **안착 판정을 모르는 색이 하나라도 있으면 전체가 중단**됩니다. red_s 가 자동 판정 불가라 순서를 마지막에 두거나 따로 돌리세요.

## 4. 기준을 다시 찍어야 할 때 (오늘 확립된 절차 — 이 순서를 어기면 값이 틀어집니다)

### 4-1. 랙 기준
1. `[▶ 시작]` 을 teach 모드로 → 랙 파지 자세에서 정지
2. 사용자가 그리퍼를 벽 진짜 중앙으로 조그
3. `[랙 보정 저장]` — 현재 TCP − 계산 TCP 를 벽 축으로 분해해 저장

### 4-2. 파지 서명 🔴 자세와 순서를 반드시 지킬 것
> **랙에서 들어올린 자세 · 그리퍼 닫은 상태**에서만 찍습니다.

- 그리퍼 벌린 픽 자세에서 찍으면 상시 **+1.6mm(파랑) / +1.05mm(노랑)** 편향
- z440 에서 찍으면 **다른 점을 물어 −37.97mm**
- 제대로 찍으면 재현 산포 **0.01mm**

🔴 **스크립트로 찍을 때 함정**: `house_cycle` 은 import 시점에 `PC.GRASP_REF` 를 `state/house/grasp_sig.json` 으로 바꿔치기합니다.
`place_calc` 만 import 하고 `save_grasp_sig_now` 를 부르면 **옛 파일 `grasp_ref_0905.json`** 에 저장돼 아무 효과가 없습니다.
반드시 `house_cycle.teach_grasp_sig(color)` 를 쓰거나 `import house_cycle` 을 먼저 하세요.

### 4-3. z440 정렬 기준
1. 벽을 문 채 z440 정렬 자세로 이동
2. 사용자가 슬롯 바로 위로 조그해 맞춤
3. `[z440 기준]` (`op=hover_ref&color=<색>&src=wrist|newcam`)

### 4-4. 슬롯 기준 (2단계)
1. 벽을 꽂은 상태에서 `[슬롯 기준 1/2]` — 안착 TCP 저장
2. 그리퍼 열고 빼낸 뒤 관측자세로 → `[슬롯 기준 2/2]` — 베이스 측정과 페어링

## 🔴 반드시 지킬 규칙 (사용자 지시)

1. **실패한 부품을 로봇이 랙에 되돌리지 말 것.** 사용자가 직접 뺍니다. 로봇은 파지점으로 복귀만.
   > "무슨 일 있어도 랙에 내려놓는 거 하지 마 이번 프로젝트에서 이렇게 하다 수업이 동결됐어"
2. **정렬 게이트를 풀지 말 것.** 풀면 어긋납니다. 검출을 보강하는 쪽으로 해결.
3. **내벽과 외벽 조건은 분리.** 외벽 4색이 도는 경로는 건드리지 않습니다.
4. **ArUco 흰 판은 고정.** 옮기지 마세요. 밑판은 매번 움직이므로 베이스 자세는 기둥 색점으로만 잽니다.
5. **실기 스택 가동 중 같은 DDS 도메인에서 테스트 금지.** 테스트는 `ROS_DOMAIN_ID=99`.
6. **기둥 진입 안전장치는 예전 그대로.**
