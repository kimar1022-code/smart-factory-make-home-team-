## 1. 진범: 화이트밸런스 5500

### 증상

- 파랑이 z+11 에서 "막힘 감시 불가(벽 점 소실)" 로 정지 (19:24)
- 내벽이 z+6 에서 세 번 연속 "막힘" 오판 (18~19시)
- **어제 저녁에도, 오늘 오전에도 안 나던 증상**

### 대조 실험 (같은 자리·같은 벽·같은 순간, WB만 변경)

| | 노출 250 | 노출 333 |
|---|---|---|
| WB 5500 (당시) | 면적 **258** | 면적 2005 |
| WB 4600 (정상) | 면적 **1823** | 면적 2159 |
| WB 5500 재확인 | 면적 **243** | 면적 2010 |

노출 250에서 파랑 점 면적이 **1823 → 258 로 7분의 1 토막**. 두 번 재현.
파랑 검출 범위가 `H 95~115, S≥150, V≥140` 인데 WB 5500이면 파랑이 시안 쪽으로 밀려 대부분 범위 밖으로 나간다.

### 왜 5500이 되었나

```
start_cam.sh:22    CAM_WB=${CAM_WB:-5500}          ← 런처가 5500 을 박아 넣음
cam_server.py:285  os.environ.get("CAM_WB","4600") ← 서버 자체 기본값은 4600 (맞는 값)
```

**서버는 4600이 맞다고 알고 있는데 런처가 5500으로 덮어썼다.** D435 가 재기동될 때마다 5500 으로 올라오고,
4600 은 누가 손으로 넣어야만 되는 값이었다. 오늘 14:59:02 에 자동복구 데몬이 D435 를 재기동했다
(`logs/cam_autostart.log`: "D435 이상(얼음 3회) → 재기동").

> 미해명 1건: 16:53 에 저장된 `color_lock.json` 에는 `wb 4600` 으로 남아 있다. 14:59 재기동 뒤 어느 시점에
> 4600 이 들어갔다가 저녁 사이에 다시 5500 이 됐다는 뜻인데, **무엇이 되돌렸는지는 어느 로그에도 없다.**
> `/expo?set=` 과 `?bright=` 는 WB 를 건드리지 않는 것으로 실측 확인했다(4600 유지).

### 막은 곳 3군데

1. `start_cam.sh` — `CAM_WB` 기본값 **5500 → 4600**
2. `tools/cam_autostart.sh` — 재기동 직후 밝기 정규화보다 **먼저** `wb=4600&awb=0` 명시 적용
3. `tools/house_cycle.py` — `check_wb()` 신설, **사이클마다 `stage_base` 진입 전에 WB 확인**하고
   4600 에서 ±50 벗어나면 되돌리고 로그에 남긴다 (`⚠ 손목캠 WB 5500 — 기준 4600 으로 되돌림`)

이제 조용히 어긋날 수 없다.

## 2. 두 번째 결함: 감시 노출 사다리가 "조각"에서 멈췄다

WB 가 진범이지만, 그 피해를 증폭한 결함이 따로 있었다.

```python
# 옛 코드 (descend_monitored)
for ex in (83, 167, 250, 333):
    ref = held_wall_dots_jam(color)
    if ref: break        # ← '점이 1개라도 나오면' 거기서 멈춤
```

저녁 조명 + WB 5500 에서 250 이 겨우 **조각 하나**(면적 236, 중심이 진짜 위치에서 18px 어긋남)를 냈고,
사다리는 거기서 멈춰 333 까지 못 갔다. 그 조각을 감시 기준으로 잡고 내려가다 조각이 사라져 정지했다.

### 고친 방식 — 게이트가 아니라 **검출 입력**을 고쳤다

- 색마다 **서명을 찍은 노출**을 먼저 쓴다 (파랑 333 · 노랑 500 · 빨강 333 · 레드_S 333)
- 서명 면적의 `SIG_AREA_OK`(0.6) 에 못 미치면 사다리를 **끝까지** 돌려 **면적이 가장 큰 노출**을 채택
- 채택 결과를 로그에 남긴다: `(막힘 감시 노출 333 채택 · 벽 점 1개 면적 2176 / 서명 1672)`
- 서명 대비 60% 미만이면 `⚠ 조명이 부족하다` 경고

**판정 문턱(`JAM_STEP_PX` 5.0 / `JAM_TOTAL_PX` 15.0 / `JAM_WIN_STEPS` 5)은 한 줄도 안 건드렸다.**

### 낮 동안 내가 넣었다가 되돌린 것 (기록용)

| 시도 | 결과 |
|---|---|
| 잘린 점의 bbox 상단 추적 | 실패 — 점이 아래로 나가며 잘리면 상단도 같이 내려간다. 철회 |
| `JAM_AREA_KEEP` 면적 급감 프레임 건너뛰기 | **위험** — 막힌 벽을 계속 눌러 내림. 철회 |
| 마지막 15mm 무감시 하강(`BLIND_TAIL_MM`) | **위험** — 같은 이유. 철회 |

셋 다 "게이트를 푸는" 방향이었고 전부 틀렸다. 진짜 답은 WB 였다.
`JAM_AREA_KEEP` 상수는 **로그 기록용으로만** 남아 있다(판정에는 안 쓴다).

## 3. run4 가 노랑에서 멈추던 결함

`SEAT_UNKNOWN_AUTO` 로 `stage_descend` 는 unknown 을 자동 완료로 넘기게 해뒀는데,
**반환값은 여전히 `seated`(=False)** 였다. run4 가 그 False 를 보고 남은 벽을 안 돌렸다.

```python
return seated or auto_done      # auto_done = unknown 을 자동 완료로 넘긴 경우
```

`not_seated`(안착 안 됐다고 **판정된** 경우)는 종전대로 멈춘다.
기준 승격은 `seated` 일 때만 하므로 unknown 이 기준으로 올라가지 않는다.

> ⚠ 이 수정은 **실제 run4 로 미검증**이다. 고친 뒤 돈 빨강·레드_S·내벽은 전부 개별 사이클이었다.

- **외벽 4색은 `descend_monitored` 그대로** — 기존 함수를 고친 게 아니라 옆에 새로 만들었다

## 6. 신설: 출하 리프트 (`tools/fork_carry.py`)

조립 끝난 집을 **포크 손잡이째** FR5 가 잡아 출하지로 옮긴다.

### 절차 (사용자 지정)

```
[속도 20] 손잡이 위 복귀 → 그리퍼 100 → z440 관측 → 파란 점 검출·XY 보정 → z280 → 그리퍼 47
[속도 10] z550 → rz 90 → x -400 → y -100 → x -700 → z285 → 그리퍼 100 개방 → z575
[속도 20] 홈(200, -330, 650)
```

한 번에 **한 축씩만** 움직인다. 매 단계 도달 오차 확인.

### 기준 (`state/house/fork.json`)

```
above_tcp   [105.0, -420.0, 440.0, 180, 0, -180]
grasp_z     280.0        lift_z 550.0        grip_open 100
expo        333          ref_px [772.02, 702.79]   ref_area 295
J           X 1mm → (+3.83, +0.02)px    Y 1mm → (-0.03, -3.94)px
inv         dx_mm = +0.2609·du,  dy_mm = -0.2541·dv
축척        0.261 mm/px (X) · 0.254 mm/px (Y)
```

**두 축이 거의 완전히 직교**한다(교차항 0.02~0.03px). 화면 X = 로봇 X, 화면 Y = 로봇 -Y.
5mm 왕복 두 번에 점이 제자리로 ±0.03px(=0.008mm) 복귀 — 벽 정렬보다 깨끗한 매핑이다.

손잡이 파란 점은 **z440 에서만 보이고 z280 에서는 화면 밖**이다. 그래서 검출·보정은 내려가기 전에
끝내고 그 뒤는 수직 하강만 한다 — 벽 픽과 같은 구조.

### 그리퍼 규칙 (★사용자가 두 번 정정한 부분)

- 벽은 "실측 > 명령 = 물림" 인데 **포크는 규칙이 반대다.** 물린 뒤 죠가 벌어지면 빠지는 중이다.
- 명령 47 을 줘도 죠는 **50 에서 멈춘다**(두 번 재현, 사용자 육안으로 물림 확인). 50 이 이 손잡이의 도달값.
- 그래서 판정 기준은 절대값이 아니라 **파지 직후 값(`HOLD_REF`)**, 거기서 `+1` 을 넘으면 즉시 정지.
- **개방은 코드에 딱 두 군데뿐이고 둘 다 자리 조건을 만족해야 실행된다** (사용자 지시: "여는 구간 아닌 데선 절대 열지 마")
  - ①시작 개방: `z ≥ 400` 일 때만 (들고 있는 중이면 거부)
  - ②내려놓기 개방: 출하지 `(-700, -100, 285)` 에서 5mm 이내일 때만

### 실기 결과 (20:5x, 1회 통과)

```
z550 상승   오차 0.03mm  그리퍼 50
rz -180→90  오차 0.00mm  그리퍼 50    ← 대회전 없이 정상
x -400      오차 0.02mm  그리퍼 50
y -100      오차 0.01mm  그리퍼 50
x -700      오차 0.02mm  그리퍼 50
z285 하강   오차 0.05mm  그리퍼 50
개방 → z575 → 홈 복귀
```

**여섯 단계 내내 그리퍼가 50에서 한 번도 안 움직였다** — 운반 중 미끄러짐 0.
페이로드를 벽 기준(0.7kg)으로 둔 채였는데 알람 없었다.

### 남은 것

- **페이로드 미등록** — 집 무게를 안 물어봤다. 지금은 0.7kg(벽 한 장) 그대로다. 무게를 알면 등록할 것.
- `grip_cmd` 를 47 로 둘지 실제 도달값 50 으로 바꿀지 미정.
- 파지 성공/실패 판정을 절대값으로 못 쓴다는 점(50 이 정상) 은 문서에만 있고 코드에는 `HOLD_REF` 로만 반영됨.
