사용자 확인(2026-09-05): **ArUco 마커가 붙은 흰 판 = 고정(안 움직임)**. **밑판(베이스) = ZK 가 놓기 때문에 언제든 비틀리거나 움직인다.**

**Why:** 이 구분이 기준계 설계 전체를 결정한다. 베이스 자세를 '화면 좌표'로 재면 로봇이 관측자세로 돌아올 때의 복귀 오차와 베이스가 실제로 움직인 것을 구분할 수 없다. 반대로 ArUco 를 베이스 추종에 쓰면 안 된다 — 마커는 고정판에 있어서 베이스가 돌아도 따라가지 않는다(9/4 재설계 문서의 표와 동일 결론).

**How to apply:**
- **베이스 자세(슬롯 위치)는 반드시 베이스에 붙은 것으로만 잰다** — 기둥 꼭대기 색점 4개(파랑2·노랑1·빨강1) + 밑판 외곽선. `tools/pillar_dots.py`, `tools/base_pose_check.py`.
- **ArUco 는 '고정 자'로 쓴다** — 베이스가 그 자 위에서 얼마나 벗어났는지가 곧 틀어짐. 사용자 아이디어를 `tools/base_twist.py` 로 구현(9/5): 기준 시점 마커 코너 ↔ 현재 마커 코너로 2D 강체+축척 변환을 구해 카메라/로봇 이동을 상쇄한 뒤, 남은 기둥 점 차이를 베이스 틀어짐으로 읽는다. 자기일관성 실측 Δ0.001mm·0.0016°, 마커 맞춤 rms 0.13px, 분해능 ≈0.03mm·0.007°(긴벽 허용 ±0.5mm·0.29° 의 1/15).
- 화면 절대좌표에 기준을 박아 두는 코드(색 검출 채점의 anchors 등)는 베이스가 움직이면 오판한다 → 채점·감시는 **밑판 꼭짓점 기준**으로. `color_lock.py` 를 그렇게 고쳤다.
