## 1. 실물 배치 (사용자 확인, 판별의 근거 — 바뀌면 `pillar_dots.py` 표도 고칠 것)
- 기둥 꼭대기 색점: **좌상 파랑 · 우상 노랑 · 좌하 파랑 · 우하 빨강**
- 벽 점: 오른쪽 벽=흰 바탕·파랑 / 아래 벽=검은 바탕·노랑 / 왼쪽·위 벽=검은 바탕·빨강
- ★**꼭짓점마다 기둥 색이 인접 두 벽의 점 색과 겹치지 않는다**(코드 `_collision_warn()` 로 자체 점검, 통과). 그래서 "위치(꼭짓점 바깥 대각)로 좁히고 → 꼭짓점별 색으로 확정 → 200×130 모양으로 검증" 이 네 벽 전부에서 성립. 색만으로는 못 가름(벽 파랑과 기둥 파랑은 H·S·V 완전히 겹침 실측, 노랑·빨강도 벽에 있음).
- 스티커 바꾸지 않기로 결정(사용자 안 "기둥 파랑·노랑/벽 빨강·초록" 은 효과 없음+벽 파이프라인 흔들림+초록은 이미 사용).
- ArUco 6장 → 사용자가 2회 재배치. 최종 **안정 4장: 30(우상,여유34mm)·35(좌상,21mm)·36(우,28mm)·37(좌,26mm)**. 33·34(아래)는 검은 아래 벽 가장자리+프레임 끝이라 해독 0 → 그대로 두거나 떼도 됨(최소 3장). 벽 투영 계산: 위·아래 변 16~19mm, 좌·우 12mm → 밑판 가장자리→마커 가장자리 **30mm** 권장.
- 흰 판(ArUco)=고정, 밑판=ZK 배치로 움직임 → [[rule-base-moves-aruco-board-fixed]].

## 3. 오늘 잡은 결함 (전부 "잘 되는 것처럼 보이는데 틀린" 종류)
1. ★★**cam_server 원본 버퍼 오염** — 오버레이(점 자리의 색 원·십자·하단 노란 글씨)를 RealSense 가 재활용하는 소스 버퍼에 직접 그려, `/raw` 30회 중 7회에 지난 프레임 그림이 섞임 → 검출 입력에 **자기가 그린 파란 원이 파란 점으로** 들어감. 몇 주간의 유령점·"골든 픽 기준 면적60 유령점 2개"·"기둥 검출 간헐 실패 23%" 의 유력 진범. 수정 후 오염 0/30, 게이트 실패 2/12→0/14. (8/28 의 `raw=img.copy()` 는 복사 시점이 아니라 '어디에 그리느냐' 가 문제였음)
2. 노출 200 은 플리커 비안전값 → 프레임마다 검출 2/4↔4/4. `start_cam.sh` 의 166 근거("120Hz 플리커 안전값") 재확인, 167 로 잠금.
3. 파랑 V 상한 235 가 반사광 화소를 잘라 덩어리 폭 15↔8px → 위치 σ 0.31mm. 상한 해제(흰 책상은 S≤103 라 채도만으로 배제).
4. 기둥 선택을 "꼭짓점에서 가장 가까운 점" 으로 하면 벽 점(벽 끝점이 더 가까움)에 속음 → 위치+색+모양 방식으로 교체. 원뿔 38°는 아래 기둥점(꼭짓점 21~40px 거리, 각 최대 62°)을 잘라냄 → 75°.
5. `detect_rect` 의 색 경계 정제 `corners` 는 검은 벽이 꽂히면 벽 바깥을 밑판 변으로 잡음(아래 변 22px 밀림) → 기둥 배정 전부 **뎁스 `box` 우선**(`PD.plate_rect`).
6. ★**감시 데몬 사고**: 마커 옮기는 동안 점수 0 → 자동 재탐색이 흐트러진 장면에서 돌아 노출 100 을 '최적'으로 저장, 167 을 덮어씀. → 감시는 복원까지만, 바닥값 미만 저장 금지로 고침.
7. `base_pose_check` 의 `m["rect"]` KeyError·`pool` NameError(라이브 첫 실행에서 잡음). 3점 폴백의 180° 뒤집힘(동률 묶음+yaw 힌트).
8. 로봇 동결(controller_dead) 진범=내가 x630 에서 z550(도달범위 밖) 명령. 전원 재투입+`fr5_up.sh`(스택 프로세스 먼저 정리) 로 복구, 동결 플래그는 관절수신 재개 시 자동 해제. **이동 전 dry_run 필수**.

## 4. 실증 숫자 (관측자세 z650, 축척 0.407mm/px, 기둥꼭대기 뎁스 377mm)
