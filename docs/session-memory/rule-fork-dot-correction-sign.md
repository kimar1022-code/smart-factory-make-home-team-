# 포크 운반(fork_carry.py) 파란 점 보정 부호 — 확정 (9/9 사용자 "보정부호 헷갈리지마 저장해")

```
Δpx = 검출 점 − ref_px                       (ref_px [772.02, 702.79], z440, expo 333)
Ji  = inv_mm_per_px  (J: X→+3.83, Y→−3.94 px/mm, 교차항 ~0)
Ji·Δpx  = 카메라(로봇)가 기준에서 어디로 가 있나
되돌릴 이동 = −(Ji·Δpx)      ← ★ 음수. dx = −(Ji00·du + Ji01·dv), dy = −(Ji10·du + Ji11·dv)
```

**9/9 실기 증명**
- 검출0 Δpx(−7.2,+6.5) → 옛 코드 (−1.90,−1.67) 이동 → 검출1 Δpx(−14.6,+10.5): J 예측(−7.3,+6.6)대로 잔차 **2배**
- 새 부호 (+1.95,+1.69) 이동 → 잔차 (−0.4,+1.3)px ≈ 0.1/0.3mm 로 **한 번에 수렴**, 사용자 "이거 맞아"

**Why:** 9/8 밤 "1회 통과 오차 ≤0.05mm" 는 손잡이가 티칭 자리에 정확히 있어 Δ≈0 이었던 것 — 0 은 부호를 뒤집어도 0 이라 버그가 실행된 적이 없었다. 9/9 집이 2mm 옮겨 놓이자 처음 실행돼 반대로 갔고, (99.5,−424.2) 치우친 파지로 운반됐다(그리퍼 49 라 "파지 OK" — 그리퍼 값은 물었는지만 알지 가운데인지는 모른다).

**How to apply:**
- `fork_carry.py locate()` 의 `dx = -(...)`, `dy = -(...)` 를 절대 되돌리지 않는다 (백업 `fork_carry.py.BEFORE_HOME_SIGN_0909` 는 틀린 부호)
- **픽셀→로봇 보정을 새로 만들면 반드시 Δ≠0 인 상태(일부러 5mm 옮겨서)로 부호를 시험**한 뒤 "성공" 이라 한다. Δ≈0 통과는 부호 검증이 아니다
- 홈 자세 = `fork.json home_tcp` (102.75,−496.36,578.36,180,0,−180)·관절 (90,−90,90,−90,−90,0). 관측자세(200,−330,650)를 홈이라 부르지 않는다 (9/8 내가 멋대로 대체했던 것, 9/9 사용자 정정)
- 파란 점이 프레임 아래 가장자리(y 709/720)에 걸려 있음 → 관측 자세를 y 로 ~10mm 옮겨 기준 재촬영 권장(미실행)
