# 생산 일시정지 / 재개 연동 — 로봇셀 회신 (2026-09-07)

받은 질문 5건에 대한 회신입니다. **이미 구현되어 있는 것**과 **새로 필요한 것**을 나눠서 적었습니다.
실기 검증 여부도 항목마다 표시했습니다 — 검증 안 된 것을 된 것처럼 쓰지 않았습니다.

---

## 0. 먼저 — Pause/Resume 인터페이스는 이미 있습니다

계약서 v0.2 §3 대로 `cell_orchestrator.py` 에 다음이 구현되어 있습니다.

```
Service  /cell/control    cell_interfaces/CellControl
  요청   ver, cmd(PAUSE|RESUME|ABORT|RESET), req_id
  응답   accepted, cell_state, detail        ← 즉시 ACK. 완료 아님

셀 상태  IDLE | EXECUTE | HELD | ABORTED | FAULT
```

동작 규칙(이미 반영됨):

- **PAUSE 는 즉시 ACK 후, 현재 안전 단위(phase)를 끝낸 시점에 `HELD` 진입** — 파지물 낙하 방지가 목적입니다.
- **`HELD` 에서 자동 재개 금지.** RESUME 명시 요청만 재개합니다(7/9 터틀봇 교훈: 자동 재개가 사고를 만듭니다).
- **ABORT ≠ PAUSE.** ABORT 및 Action Cancel 은 `status = "CANCELED"` 로 종료, 장비·비전 오류는 `"FAILED"`.
  말씀하신 "Cancel 은 별도 안전 종료" 구분과 이미 일치합니다.
- 오류로 `HELD` 가 된 경우(E101/E201/E301)는 RESUME 으로 못 이어갑니다 — RESET 후 Task 재발주입니다.

즉 **질문 2·4 는 이미 충족**되어 있고, 이번에 새로 필요한 것은 **"phase 경계까지 기다리지 않고 지금 움직이는 모션을 즉시 세우는 것"** 입니다.
아래는 그 관점의 답변입니다.

## 1. ExecuteTask 수행 중 FR5 / ZK2 의 현재 motion 을 controlled stop / hold 할 수 있는가

### FR5 — 가능합니다 (기구조상 controlled stop)

- FR5 모션은 **MoveIt2 `MoveGroup` 액션 골**로 나갑니다. 골을 취소하면 컨트롤러가 **감속 정지**합니다.
  브리지에 이미 `stop()` 이 있고 내부적으로 이 취소를 씁니다 — E-Stop(급정지)이 아니라 소프트웨어 감속 정지입니다.
- 카테시안 직선 구간(삽입 하강 등)은 저희가 **3mm 단위 스텝**으로 쪼개 실행합니다(비전 막힘 감시 때문).
  따라서 "스텝 사이 정지"만으로도 실질 지연 **1스텝 ≈ 1초 이내**입니다.

⚠ 주의(실기에서 겪은 것):
- **정지 직후 다른 명령을 겹치면 컨트롤러가 동결**됩니다. 예외 경로에서 정지를 선행하지 않아 기둥을 파손한 사고가 있었습니다(9/2).
  → Pause 처리에서 `stop()` 이 **완료 확인된 뒤에** 상태를 `HELD` 로 바꾸도록 하겠습니다.
- 과거 STOP 이 동결을 유발하던 원인(홀드 스냅)은 가감속 리미터 플러그인으로 해결했습니다(8/26).

### ZK1 / ZK2 — 가능하지만 조건이 붙습니다

- ZKBOT 은 PLC 조그 비트(Modbus RTU)로 움직입니다. **비트를 끄면 드라이브 프로파일대로 감속 정지**합니다.
  이것도 E-Stop 이 아니라 소프트 정지라 **원점(호밍)이 유지**됩니다.
- ⚠ **리모컨 비상정지나 모드 전환은 원점을 잃습니다**(8/20 실측). Pause 는 반드시 소프트 경로로만 해야 합니다.
- ⚠ **끊어치기 금지**(8/6): 짧은 시작·정지를 반복하면 정밀도가 무너집니다. Pause 는 드물게, 재개는 목표 재지정으로 갑니다.

## 2. pause 시 task / step 진행 상태를 유지한 채 resume 시 이어서 수행할 수 있는가

**가능합니다. 이미 그렇게 동작합니다.**

- `ExecuteTask` 골 핸들과 진행 상태(`run`: 현재 phase, current_item, 완료 슬롯 목록)를 **오케스트레이터가 들고 있는 채** `HELD` 로 들어가고,
  RESUME 이 오면 그 지점부터 이어서 phase 시퀀스를 계속합니다. Action 은 살아 있습니다(재발주 불필요).
- 완료된 슬롯은 `completed_json` 에 누적되므로, 중간에 ABORT 로 끊겨도 어디까지 됐는지 서버가 판단할 수 있습니다.

**즉시정지까지 넣을 때 추가로 필요한 것** — phase **중간**에서 멈추면 "그 phase 를 어디까지 했는지"를 알아야 합니다. 저희 방침은:

> **재개는 이어붙이기가 아니라 "그 phase 를 다시 시작"** 으로 합니다.

이유가 있습니다. 저희 phase 는 전부 **절대 목표**(측정 → 목표 TCP 계산 → 이동)이고, 비전 측정은 매번 새로 합니다.
중간 상태를 복원하는 것보다 **다시 측정해서 다시 가는 쪽이 안전하고 결과도 같습니다**.
단, 이미 물건을 물고 있으면 파지를 유지한 채 그 phase 만 재실행합니다(아래 3번).

## 3. 파지 / 흡착 중 pause 시 gripper / vacuum 상태를 유지할 수 있는가

### 그리퍼(FR5) — 유지됩니다

- 그리퍼는 **위치 지령형**이라 새 명령을 안 보내면 그 개도를 그대로 물고 있습니다. Pause 중 그리퍼 명령을 보내지 않는 것이 규칙입니다.
- ⚠ **그리퍼 동작 자체는 중단하면 안 됩니다.** 풀스트로크 실측 **11초**이고, 과거 `max_time` 을 짧게 줬을 때
  ServoJ 오류 14 → errno73 연쇄로 **전원 재투입 말고는 복구가 안 되는 알람**이 났습니다(8/14).
  → 그리퍼 개폐 중 PAUSE 는 **즉시정지 대상에서 제외**하고, 동작 완료 후 HELD 로 갑니다(최대 11초).

### 흡착(ZK) — 유지됩니다. 다만 안전장치가 필요합니다

- 진공은 출력 유지형이라 Pause 중 그대로 붙어 있습니다.
- 🔴 **진공에는 피드백이 없습니다**(계약 §6 의 E201 을 저희가 검출할 수 없음, 8/11 기록).
  즉 **Pause 가 길어지면 부품이 조용히 떨어져도 아무도 모릅니다.**
  → 두 가지를 제안드립니다: ① **흡착 상태 Pause 최대 시간**을 정해 초과 시 FAULT 로 올릴 것,
  ② **RESUME 시 재검증**(비전으로 부품 유무 확인) 후 진행할 것.

## 4. Pause / Resume 용 ROS2 Service 또는 별도 제어 인터페이스 추가가 가능한가

**가능하며, 이미 `/cell/control` 이 그 인터페이스입니다.** 즉시정지를 위해 **필드 하나만 추가**하면 됩니다.

```diff
  # CellControl.srv
  string ver        # "0.2" → "0.3"
  string cmd        # PAUSE | RESUME | ABORT | RESET
  string req_id
+ bool   immediate  # true = 현재 모션까지 즉시 감속 정지(안전 구간이면)
+                   # false/미지정 = 기존 동작(현재 phase 완료 후 HELD)  ← 기본값
  ---
  bool   accepted
  string cell_state
  string detail
+ string held_at    # 실제로 멈춘 지점: "PHASE_BOUNDARY" | "MID_MOTION" | "DEFERRED_UNSAFE"
```

- `immediate=false` 를 기본값으로 두면 **기존 연동은 그대로 동작**합니다(하위 호환).
- `held_at` 으로 서버가 "즉시 섰는지, 안전구간이라 미뤘는지"를 알 수 있게 하겠습니다.
  음성 UX 에서 "지금 멈췄습니다" / "동작 마무리 후 멈춥니다" 를 구분해 안내하실 수 있습니다.
- 상태 조회는 기존 `/cell/status` 의 `cell_state` 그대로입니다.

별도 인터페이스가 더 편하시면 `/cell/pause_immediate` (std_srvs/Trigger) 를 얇게 하나 더 두는 것도 가능합니다.
다만 **명령 창구는 하나로 두는 편**이 상태 일관성에 유리해서 위 방식을 권합니다.

## 5. 즉시 정지가 불가능한 구간과, 그때의 safe point

| 구간 | 즉시정지 | 이유 / 대신 멈추는 지점 |
|---|---|---|
| MOVE, OBSERVE, RETREAT (자유 공간) | ✅ 가능 | 감속 정지 후 그 자리에서 HELD |
| PLACE_APPROACH (삽입 전 호버) | ✅ 가능 | 이 자리가 가장 안전한 대기점 |
| **INSERT — 벽이 기둥 채널 안** | ⚠ 조건부 | 정지 자체는 됨. 단 **3mm 스텝 경계**에서 멈춤(지연 ≤1초). 스텝 중간 정지는 벽이 그리퍼에서 밀릴 수 있음 |
| **그리퍼 개폐 중** | ❌ 불가 | 풀스트로크 11초, 중단 시 알람→전원 재투입(8/14). 동작 완료 후 HELD |
| **흡착 붙이기 / 떼기 중** | ❌ 불가 | 진공 피드백이 없어 중간 상태를 알 수 없음. 완료 후 HELD |
| **ZK 수직 리프트(부품 든 채)** | ⚠ 조건부 | 리프트 완료 지점까지 진행 후 HELD. 중간 정지는 미끄러짐 위험 |
| 비전 측정 중 | ✅ 가능 | 로봇이 안 움직이는 구간이라 그 자리에서 즉시 |

**권장 safe point 정의** — 아래 넷 중 가장 가까운 곳에서 멈춥니다.

1. phase 경계 (기존 동작)
2. 삽입 하강의 **스텝 경계** (3mm 또는 10mm 단위)
3. **호버 자세**(z_seat + 85, 삽입 직전 대기점)
4. 관측 자세

즉시정지 요청이 ❌ 구간에서 들어오면 **거부하지 않고 `held_at="DEFERRED_UNSAFE"` 로 ACK 한 뒤 가장 가까운 safe point 에서 정지**합니다.
최악 지연은 **그리퍼 개폐 11초**, 그 외에는 1초 이내입니다.

## 정리

| 질문 | 답 | 상태 |
|---|---|---|
| 1. 수행 중 controlled stop / hold | 가능 (FR5=골 취소 감속, ZK=조그 비트 OFF) | FR5 stop 실기 검증됨 / **즉시정지 경로는 미검증** |
| 2. 상태 유지 후 이어서 재개 | 가능. 단 재개 단위는 **phase 재시작** | phase 경계 PAUSE/RESUME 는 **구현·모의 검증 완료** |
| 3. 파지·흡착 유지 | 유지됨. 흡착은 **피드백 없음** → 최대 Pause 시간 + 재개 시 재검증 필요 | 그리퍼 유지 실기 확인 / 흡착 장시간 미검증 |
| 4. Service 추가 | `/cell/control` 에 `immediate`·`held_at` 필드 추가 (하위 호환) | 스키마 개정 필요 — **v0.3 합의 요청** |
| 5. 즉시정지 불가 구간 | 그리퍼 개폐, 흡착 동작, ZK 리프트(부품 든 채). safe point 4종 | 위 표 |

### 저희가 요청드리는 것

1. `CellControl.srv` 를 **v0.3 으로 개정**(`immediate`, `held_at` 추가) 승인.
2. **흡착 상태 최대 Pause 시간** 값 지정 (저희 제안: 60초, 초과 시 FAULT).
3. 음성 "일시정지" 가 **immediate=true 로 오는지 false 로 오는지** 확정.
   강사님 피드백대로 "즉시 멈춤"이면 true 이지만, 그 경우 위 표의 ❌ 구간에서는 최대 11초 지연이 있음을 UX 문구에 반영 부탁드립니다.

### 일정

즉시정지 경로는 **아직 실기 검증 전**입니다. 스키마 합의 후 구현 → 도메인 99 격리 모의 → 실기 순으로 진행하겠습니다.
