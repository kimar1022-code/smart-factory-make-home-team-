# 9/10 — A타입 6벽 완주 + 기준 체계 정리

## 한 줄 요약

**하루 종일 벽이 2~6mm 씩 어긋나 삽입이 실패했다. 원인은 하나였다 —
`slot_ref`(계산 목표)가 실제로 들어가는 자리를 모르고 있어서, 호버 기준을 찍은 자리와
사이클이 도착하는 자리가 어긋나 있었다.** 색마다 "그 벽이 실제로 꽂히는 자리"에서
기준을 다시 잡자 정렬 잔차가 **2~6mm → 0.03~0.17mm** 로 떨어졌다.

---

## 1. 진범: 기준 자리 ≠ 도착 자리

정렬은 `(지금 화면) − (기준 화면)` 만 본다. **기준 자체가 틀린 자리에 있으면 그것을 알 방법이 없다.**
옳은 자리를 아는 것은 `slot_ref`(사람이 손으로 앉힌 안착 TCP ↔ 그때 베이스) 하나뿐이다.

한 뿌리에서 세 가지 증상이 갈라져 나왔다.

| 증상 | 실제 원인 |
|---|---|
| `베이스 특징 매칭 0개` (기둥이 15.7px 밖) | 매칭이 **기준 픽셀 주변만** 뒤진다. 3mm 떨어지면 기둥은 16~20px 밀려 보인다 |
| `카메라 불일치 1.5~1.9mm` | 거리에 비례해 J(축척·방향) 오차가 커진다. **기준 자리에서는 0.099mm 로 일치** |
| 정렬이 2~3mm 끌어내 기둥에 막힘 | 기준 자리로 끌고 가는데 그 자리가 정답이 아니다 |

### 해결
`하강+기준재촬영`(descend_reteach) 으로 **검증된 자리에서 슬롯 기준을 갱신**.
갱신 직후 같은 색 사이클: 두 캠 불일치 **0.10mm**, 정렬 이동 **0.74mm**, 슬롯 대비 **0.57mm**
(그전 1.5~1.9 / 2.1~3.4 / 2.15~2.46mm).

```
red_s   seat (235.20, -311.29, 355.51) → (236.20, -311.27, 355.0)
yellow  seat (243.75, -515.99, 351.0)  → (243.13, -511.97, 351.0)   4.07mm 이동
blue    seat (177.36, -414.90, 351.99) → (175.50, -412.30, 351.99)
red     seat (307.00, -414.00, 354.18) → (304.48, -410.58, 354.18)
```

밤에 B타입도 같은 정비를 했더니 **일관되게 5.2~6.3mm** 어긋나 있었다 — 9/9 이후 밑판이 그만큼 움직인 것.

## 2. 기준 체계 확정 (사용자 지정)

**외벽 4색 — 카메라마다 두 점: `기둥 1 + 든 벽 1`**

| 벽 | 손목캠(뎁스) | 새카메라 |
|---|---|---|
| blue | 기둥 yellow / 든 벽 blue×2 | 기둥 red / 든 벽 blue |
| yellow | 기둥 blue / 든 벽 yellow | 기둥 blue+yellow / 든 벽 **옆면 red** |
| red | 기둥 blue / 든 벽 red | 기둥 blue / 든 벽 red |
| red_s | 기둥 red / 든 벽 red | 기둥 blue+red / 든 벽 **옆면 yellow** |

**내벽 2색 — 밑판 노란 점만**

| 벽 | 기준 |
|---|---|
| blue_in | 밑판 바닥 노랑 **3점** (+든 벽 2점, 새카메라 미사용) |
| yellow_in | 밑판 바닥 노랑 **2점** (든 벽 점이 어느 자세에서도 안 보임 → 밑판 기준 모드) |

`state/house_*/pillar_pick.json` 에 저장. **지정하지 않으면 검출된 밑판 특징이 전부 기준에 들어가고,
거기엔 이미 꽂힌 벽의 점이 섞여 그 벽이 빠지는 순간 기준이 무너진다.**

## 3. 코드 변경

### `hover_align.py`
- **예측 이동 매칭** `_pred_shift_px()` — 기준 tcp 대비 지금 tcp 차이를 `J = inv(Jinv)` 로 픽셀 환산해
  **기둥 검색 중심을 옮긴다**(벽 점은 로봇과 함께 움직이므로 안 옮김). 반경 15px 은 그대로 = 완화가 아니다.
  실측 검증: Δ로봇 (+2.70,−2.04)mm → 예측 (+11.2,−14.6)px, 실측 (+7,−14)px, 잔차 4.2px.
  ⚠`sim` 은 **원래 기준 픽셀 → 지금** 이어야 하므로 매칭 후 `s_` 를 되돌린다.
- **`WALL_COLOR_BY_SRC`** — (색, 카메라)별 '든 벽 점' 색.
  `{("red_s","newcam"):"yellow", ("yellow","newcam"):"red"}`
  규칙 = **"그 화면에서 유일한 색을 고른다."** 새카메라는 팔에 붙어 자리마다 시야가 바뀐다.
- **`pillar_pick` 여러 점 지원** — `[x,y]` 또는 `[[x,y],...]`
- **`BASE_ONLY_ALIGN`** — 든 벽 점이 없는 색(yellow_in)은 **로봇을 밑판에 맞춘다**.
  `dmm = -Jinv·(밑판 특징 이동)`. 실측 검증: +3mm 이동 → 제안 −3.017mm(오차 0.02mm)
- **`EXPO_SETTLE_S = 1.4`** — 노출 변경 후 대기 0.6s → 1.4s(사다리 포함 4곳).
  0.6s 면 전환 중 프레임을 읽어 측정이 실패하거나 5mm 튄 것처럼 보인다
- **지정 없으면 기준 저장 거부** — 넓게 저장되는 것을 구조적으로 차단(거부 시 검출 후보 목록 출력)
- **`role="measure"` 카메라의 측정 실패는 정렬을 멈추지 않는다** — 조종 안 하는 눈이 못 봤다고 멈출 이유가 없다
- `HELD_BOX_BY_COLOR` / `HELD_AMIN_BY_COLOR` — 자세가 다른 색의 든 벽 점 창 보정
- `WALL_DOT_HSV["yellow_in"]` V 하한 120 → **80**(저녁 실측 H21 S200 V97)

## 4. 측정 실측치

**검출 재현성** (고정 새카메라 25프레임, 최근접 추적)

| 점 | σ | 최대편차 | 면적 변동 |
|---|---|---|---|
| 빨강 기둥 | (0.38, 0.20)px | 0.83px | 2% |
| 파랑 기둥 | (0.59, 0.71)px | 2.89px | 10% |

손목캠 축척 0.18mm/px → σ ≈ **0.07~0.15mm**.
정렬은 **같은 프레임의 두 점 차이**만 쓰므로 공통 오차가 상쇄 → 상대 잡음 **0.02mm**.
노출 83↔250 차이 **0.1px**(단, 정착 1.2초 필요).

**진짜 위험은 잡음이 아니라 "다른 점을 잡는 것"** — 블롭이 조각나면 중심이 **3.2mm** 이동(9/8 실측).
20~60배 차이. 그래서 방어가 전부 "같은 점인가"에 걸려 있다(15px 매칭 반경 · 면적 게이트 0.6~1.6배 ·
`pillar_pick` 화이트리스트 · 노출 사다리).

**전체 사슬 재현성**: 같은 기준으로 3회 dy +0.881/+0.957/+0.836 → **±0.05mm**

## 5. 사고와 교훈

### 🔴 z440 낙하 — 파일만 고치고 사이클을 재시작 안 했다
`red_s` 슬롯 기준에 안착 z 가 **440.02** 로 잘못 저장된 것을 파일에서 355 로 고쳤는데,
**돌고 있던 사이클이 메모리에 들고 있던 옛 값은 안 바뀌었다.** 하강이 "이미 도착했다"고
판단해 z440 에서 그리퍼를 열어 벽을 **85mm 위에서 떨어뜨렸다.**
→ 하강 직전 파일 재확인 + 20mm 가드 추가.

### 벽 옆면 점 — 좋은 아이디어, 하지만 XY 조종은 금지
사용자가 벽 옆면에 점을 추가. 손목캠(수직)은 원리적으로 못 보고 **새카메라(비스듬)만** 본다.
- 검출 재현성 σ 0.12~0.16px = **0.04mm**, 화면에서 유일한 색이라 오검출 0
- 🔴**옆면 점으로 XY 를 조종하면 안 된다** — 비스듬한 시야라 벽이 죠 안에서 **위아래로** 달라지면
  화면에서 세로로 움직이고 매핑이 그걸 **가로 이동으로 읽는다**
  (기준과 같은 파지: 두 캠 0.099mm / 파지 가로 1.53→0.51 로 바뀌자 새카메라만 +1.45mm)
- → `ALIGN_ROLES` 에서 **`measure`(감지기)** 로 쓴다. 두 캠 차이가 커지면 = "파지가 기준과 다르다"

### 파지 게이트는 옳았다
15:35 red_s 막힘의 직접 원인 = **랙에 1.44mm 다른 자리에 꽂혀** 파지 가로 +1.53mm(게이트 1.0mm 초과)
인데 [▶계속] 로 통과. **1점 정렬은 벽이 아니라 그 점을 맞춘다** → 점은 맞고 벽은 2.4mm 틀어짐 →
z+73 에서 막힘(막힘 감시가 25mm 후퇴, 손상 0). 랙에 제대로 꽂으니 +0.51mm 로 통과.

### 함정
- 이미 열려 있는 그리퍼에 또 열기 명령 → **409 Conflict**(그리퍼 동작이 제어 루프 2~5초 점유,
  동결 감시 4초가 오판). 값이 같으면 보내지 말 것
- 노출 실험 후 **원복 안 하면** 다음 하강이 "막힘 감시용 벽 점 없음"으로 거부
- `cam_autostart.sh` 데몬이 "밝기 정규화"로 **노출을 붙들고 있다** — `/expo?exposure=` 가 무시된다.
  게인만 반응
- 로그에 날짜가 없어 `awk` 로 시각만 잡으면 **어제 것까지 딸려 온다**
- 색 등록 확인한다고 `slot1` 을 부르면 **지금 자리가 슬롯 기준으로 저장된다**
- house_cycle 재기동은 WAIT DESCEND 상태(목표·정렬)를 잃는다 → **하강 끝난 뒤** 재기동
