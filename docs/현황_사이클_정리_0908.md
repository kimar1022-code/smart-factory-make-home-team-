## 2. 사이클이 실제로 어떻게 도는가

`house_cycle.py` (:8776). 한 벽을 넣는 한 사이클은 아래 순서로 간다.

```
① 1 BASE      관측자세(200,−330,650)에서 밑판 기둥 색점 4개로 베이스 자세 측정
              · 건강 게이트 = 4프레임 중 3프레임이 4/4 검출 + rms < 2.5mm
              · ArUco 흰 판을 '고정 자'로 써서 카메라 드리프트 보정
              · 실패하면 노출 사다리(8~500) + gain 사다리로 재시도

② 2 RACK      랙 SAFE → 그리퍼 열기 → 랙 관측자세 → 벽 양끝·가운데 점 측정
              · 색별 저장 노출을 먼저 맞춤 (노출이 다르면 각 0.33°·파지 1.4mm 틀어짐)
              · 길이 게이트 ±2%, 각 게이트 ±3.0°
              · 파지 XY 계산 → 하강 → 그리퍼 닫기 → 들어올림(+125mm)
              · 파지 서명과 대조해 파지 편차 측정 (게이트 1.0mm / 0.7°)

③ 2' CARRY    SAFE 상승 → 목표 XY 위에서 rz 정렬 → z478 → z(안착+HOVER_DZ)

④ 2' HOVER    ★핵심. 든 벽 점 ↔ 베이스 특징을 같은 화면에서 기준 관계에 맞춘다.
   ALIGN      · 파지가 어디를 물었든 무관해진다
              · 수렴 0.3mm/0.15°, 최소 실행 이동 0.8mm 미만이면 '한계 수렴'
              · 끝나고 정렬 온전성 검사 (슬롯 기준 대비 4mm)

⑤ WAIT       🔴 **사람이 [⬇ 하강] 을 눌러야 진행** — 유일한 필수 개입
   DESCEND

⑥ 3 DESCEND   3mm × 6회 → 10mm × n → 마지막 15mm 는 다시 3mm
              · 매 스텝 손목캠으로 든 벽 점을 보고 밀림 감시
              · 5스텝 창 누적 15px(≈1.4mm) 넘으면 막힘 → 25mm 상승 → ③부터 재시도

⑦ 3 SEAT      안착 판정 (아래 3절)
   CHECK      · seated → 호버·안착·슬롯 기준 3종 자동 승격
              · unknown → 🔴 **그리퍼 문 채 정지, 사람이 육안 확인 후 [▶계속]**

⑧ 3 RELEASE   그리퍼 열기 → 수직 +30 → z478 → SAFE
              · (9/8 신설) 측면캠 안착 확인 — 기준 없으면 학습, 있으면 판정
```

## 3. 안착 판정 — 유일하게 안 되는 부분

### 지금 방식과 그 한계

손목캠·새카메라로 **기둥 색점**을 본다. 두 카메라 모두 손목에 붙어 있어서,
"안착 TCP 에 있을 때 기둥이 기준과 같은 픽셀에 오는가"로 *간접* 확인하는 구조다. 허용 12px.

구조적으로 아래 상황에서 원리적으로 못 한다.

1. **안착 높이에서 기둥이 화면에 없다** — red_s(z351), red_in(z338). 오늘 2회 실패.
2. **벽이 늘면 기둥이 가려진다** — 마지막에 넣는 벽일수록 불리하다. 오늘 red_in 2회차가 이 경우
   (기준 기둥 2개 중 1개만 보임).
3. **경계에 걸린다** — blue 가 12.008px 로 0.008px 초과해 탈락. 노랑은 빨간 점 3.6px 인데
   파란 점만 24.3px 로 한 점만 튐.

### 해법 — 측면캠(:8771) 판정 (9/8 신설, `tools/side_seat.py`)

측면캠은 **고정**이다. 이 차이가 결정적이다.

- 로봇 자세와 무관 → **안착 높이에서 기둥이 안 보여도 상관없다**(red_s·red_in 해결)
- 위에서 비스듬히 보므로 벽이 늘어도 가림이 덜하다
- **벽 자체를 직접 본다** — 추론이 아니라 관측
- 고정이라 흔들리지 않는다: 5프레임 반복 산포 **0.04~0.2px** (손목캠은 3px 대)

**원리**: 이 벽을 뺀 나머지 전부(기둥 점 + 이미 꽂힌 다른 벽의 점)가 곧 '베이스'다.
그 점들로 베이스의 이동·회전을 풀어 기준 벽 점을 옮긴 뒤, 실제 벽 점과 비교한다.
베이스가 움직여도 상대 비교라 무관하다.

**벽 점을 가려내는 법**: 꽂기 전 한 장(로봇이 랙에 있어 화면 밖) + 꽂고 물러난 뒤 한 장.
새로 생긴 점 = 이 벽의 점. 둘 다 있는 점 = 기준점. 사이클에 자동으로 배선되어 있다.

**실측 결과 (red_s, 9/8 12:08)**
```
기준점 13~15개 짝맞춤   rms 0.1~0.3px    ← 베이스 변환이 정확
벽 점 위치 잔차          1.3 ~ 6.2px      ← 허용 10px
```
**위치 정확도는 이미 손목캠보다 한 자릿수 좋다.** 원리는 증명됐다.

**남은 문제**: 검출률. 벽 점 7개 중 4~6개만 잡힌다. 원인을 실측했다.
```
blue (487,236)  0/12   ← 로봇이 비켜나며 생긴 허상이 기준에 들어갔음(기준 생성 시 걸러야)
blue (936,352) 11/12   면적 중앙값 29  ← 면적 하한 30 에 딱 걸림
blue (868,415) 11/12   면적 중앙값 35  ← 역시 경계
blue (980,441)  6/12   면적 90        ← 면적은 큰데 절반만. 반사로 추정
red  (976,316) 12/12   면적 100       ← 안정
red  (901,382) 12/12   면적 108       ← 안정
```
→ 면적 하한 **30 → 12**, 프레임 5 → 7, 필요 관측 4 → 5 로 조정했다(게이트 완화가 아니라
검출 보강). 기준 생성 때 여러 번 관측해 **항상 보이는 점만** 남기도록도 고쳤다.
**아직 조정 후 재검증은 못 했다.**

## 4. 어디를 자동화해야 하는가

지금 사이클에서 **사람이 개입하는 지점은 정확히 세 곳**이다.

### 🔴 ① 하강 버튼 (매 사이클 1회, 필수)
정렬이 끝나고 `WAIT DESCEND` 에서 반드시 사람이 [⬇ 하강] 을 눌러야 한다.

- **의도된 안전장치다.** 벽이 기둥 채널로 내려가는 순간이 물리적으로 가장 위험하고,
  9/2 에 기둥을 부러뜨린 전과가 있다.
- 자동화하려면 "정렬 결과가 충분히 좋으면 자동 진행" 규칙이 필요하다.
  오늘 데이터로 보면 온전성 0.23~1.70mm 로 전부 여유가 컸으니,
  **온전성 < 2.0mm 이고 막힘 감시가 살아 있으면 자동 하강**이 현실적인 후보다.
- 무개입 시연을 하려면 이걸 열어야 한다. **단, 판정(②)이 먼저 신뢰 가능해야 한다.**

### 🔴 ② 안착 확인 (오늘 6번 중 5번)
`unknown` 이 나오면 사람이 눈으로 보고 [▶계속] 을 눌러야 한다.

- **이게 지금 가장 큰 병목이다.** 측면캠 판정이 답이고, 위 3절대로 원리는 증명됐다.
- 남은 작업: 검출 조정 재검증 → 색별 기준 학습(각 색 1회 삽입) → 판정 정확도 확인.
- 여기가 자동화되면 ①도 안전하게 열 수 있다. **판정 없이 하강만 자동화하면 안 된다** —
  잘못 들어가도 아무도 모르는 상태가 되기 때문이다.

### 🟡 ③ 파지 편차 게이트 초과 (오늘 6번 중 2번)
파지가 1.0mm / 0.7° 를 넘으면 [▶계속] / [⛔중단] 을 묻는다.

- 오늘 노랑(가로 −1.43mm)·red_s(각 +0.96°) 두 번. 둘 다 [▶계속] 로 진행해 잘 들어갔다.
- 위치 초과는 z440 정렬이 실제로 보정한다(노랑: 정렬이 y 를 2.5mm 옮김 → 온전성 1.66mm 로 통과).
- **각 초과는 red_s·red_in·yellow 가 손목캠 단독 XY 정렬이라 보정되지 않는다.**
  rz 는 랙에서 잰 각으로 고정된다. 126mm 벽에서 0.96° 면 양 끝 약 1mm 차이.
- 자동화 후보: **위치 초과는 정렬에 맡기고 자동 진행, 각 초과는 계속 사람에게 묻기.**
  다만 오늘 표본이 2건뿐이라 근거가 얇다.

### 그 밖에 자동화하면 좋은 것 (사람 개입은 아니지만 손이 감)

- **화이트밸런스 복구.** D435 가 재기동되면 WB 가 4600 → 5500 으로 돌아가고, 그러면
  색점 검출이 통째로 무너진다. 오늘도 두 번 손으로 되돌렸다.
  → `cam_autostart` 의 '색점 노출 복원' 경로에 **WB 4600 고정**을 넣어야 한다.
- **빈 베이스에서 기둥 검출 실패.** 벽이 하나도 없으면 기둥 색점이 잘 안 잡힌다
  (9/8 11:39 실측: 노출 사다리 전부 0/4). 벽이 한 장이라도 있으면 4/4 통과.
  → 첫 벽만 취약. 기둥 점 스티커 보강이나 빈 베이스 전용 검출이 필요하다.
- **안착 기준 자동 갱신.** 오늘 blue 12.008px, yellow 24.3px 는 기준이 어제 자리에서
  찍혔기 때문으로 보인다. 성공 사이클마다 기준이 승격되지만, `unknown` 이면 승격이 안 되므로
  **한번 어긋나면 계속 어긋난 채로 남는다.** 측면캠 판정이 붙으면 이 고리가 풀린다.
